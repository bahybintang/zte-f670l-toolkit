# Network menu (mmNet, without WLAN): mapping notes

Source of truth: `pages/network.json` (32 pages). Stock files are in `debug/clone-fw/httpd/`.
These notes cover where each value is stored, where the enum codes come from, and what is still unverified.

## Enum codes: where they come from

The stock gch pages talk to `OBJ_*` objects in **web strings** (`AlwaysOn`, `PAP,CHAP,MS-CHAP`,
`DHCP`, `IP_Routed`). The DB stores **integers**. libcmapi converts between the two using
exported `{char*, int}` tables. The tables were read from the reference firmware
`debug/ref-fw-v9/extracted/lib/libcmapi.so`: each `.data` symbol `t*Table` is a list of
(string, int) pairs. The tables used here:

| Table symbol | Codes (string → DB int) | Used for |
|---|---|---|
| tWANCAPPConnTypeTable | Unconfigured 0, IP_Routed 1, IP_Bridged 2, DHCP_Spoofed 3, PPPoE_Bridged 4, PPPoE_Relay 5, PPTP_Relay 6, L2TP_Relay 7 | WANC.ConnType |
| tWancPPPConnTriggerTable | AlwaysOn 0, OnDemand 1, Manual 2 | WANCPPP.ConnTrigger |
| tWancPPPAuthTypeTable | PAP,CHAP,MS-CHAP 0, PAP 1, CHAP 2, MS-CHAP 3 | WANCPPP.AuthType |
| tWANCIPAddressingTypeTable | DHCP 0, Static 1, AutoIP 2 | WANCIP.Addressingtype |
| tWANCIpModeTable | IPv4 1, IPv6 2, Both 3 | WANC.IPMode |
| tWANCDLINKType | Unconfigured 0, OE 1, EoA 2, PPPoA 3, IPoA 4, CIP 5, PPPoTTY 6, STA 7, 3GDHCP 8 | WANCD.LinkType |
| tWANCApplicationTable | firewall 1, ddns 2, dns 3, sntp 4, upnp 5, igmpproxy 6, voip 7, tr069 8, route 9, binding 10, traceroute 11, vsftpd 12, mldproxy 13, tunnel46 14, tunnel64 15 | WANCServList.Application (16 is in the factory DB but not in the table) |
| tWANCWBDModeTable | Transparent 0, Tag_Drop 1, Tag_Transparent 2 | WANC.WBDMode (see below) |
| tBrGrpAddressingTypeTable | DHCP 0, Static 1, AutoIP 3 | LAND.AddressingType |
| tROUTEEntryTypeTable / StatusTable | Default 0, Network 1, Host 2 / Disabled 0, Enabled 1, Error 2 | L3ForwardingRT |
| tRIPProtocol / tRIPAuthType | '0'→1 '1'→2 '2'→3 / '0'→0 '1'→2 '2'→3 | RIPConf |
| tSntpConfDayTimeTypeTable, tDHCPPortControlTable, tIPv6AcquireMode, tIP6PFX* | — | for reference |

The WAN user page (`net_user_wan_conf_t.gch`) has a mode select with option values `IP_Routed` (PPPoE) and
`PPPoE_Bridged` (Bridge). The factory hidden WAN row has ConnType 4. Both facts confirm the ConnType codes.

**WBDMode has two readings.** The stock JS sends the numbers 0/1/2, labelled UnTag, Transparency and Tag,
and requires VLAN 1-4094 when the value is 2. The cmapi table names those same numbers Transparent,
Tag_Drop and Tag_Transparent. The schema uses the web labels. Verify on the device by setting a tagged
WAN in the stock UI and reading `sidbg 1 DB p WANC`.

**RIP:** the int column of the table gives the schema's DB codes (protocol 1/2/3, auth 0/2/3). The web page's
auth option values are 0/2/3 but the table's string column is '0','1','2'. Read RIPConf on the device to
confirm which direction is correct.

## WAN (`wan`, ssmETHWANCon, net_ethwan_conf_t.gch)

### How the stock page creates a connection

1. The page picks a handler from the type: `ethwancppp_gch.gch` (PPPoE / PPP / PPP_both), `ethwancip_gch.gch`
   (Static / DHCP / IP / IP_both) or `ethwancbridge_gch.gch` (BRIDGE).
2. On *Create* the JS fills hidden fields at index = IF_INSTNUM and posts `IF_ACTION=new`. The handler then calls
   `set_inst(handle, "OBJ_ETHWANCPPP_ID"|"OBJ_ETHWANCIP_ID"|"OBJ_ETHWANCBRIDGE_ID", "")`. The empty
   identity means create. libcmapi (`CmWANCAddIP`, `CmAddPPPIF`, `CmWANDAddWancd`…) creates the DB rows.
3. *Modify*: `IF_ACTION=apply` → `set_inst` with the identity. *Delete*: `del_inst(obj, identity)`.
4. The connection name (`WANCName`, e.g. `1_INTERNET_R_VID_…`) is generated by the firmware; the user does not set it.

### Rows and their links (ViewName join; row numbers differ per table)

```
WAND        IGD.WD1
 └ WANCD    IGD.WD1.WCDn            (WANDViewName = IGD.WD1; LinkType 1 = oE)
    ├ MultiWancd IGD.WD1.WCDn.MultiWancd   (WCDViewName = IGD.WD1.WCDn; VlanMode, WanVlan, WanPri)
    └ WANC  IGD.WD1.WCDn.WCPPPm | .WCIPm  (WANCDViewName = IGD.WD1.WCDn; common fields)
        ├ WANCPPP | WANCIP  same ViewName as the WANC row (type-specific fields)
        ├ WANCEXT     IGD.WANC_EXTk  (WANCViewName = WANC ViewName; DhcpEnable)
        └ WANCServList IGD.WANCSLk   (WANCViewName = WANC ViewName; Application code), one row per app
```

- A bridge WAN is a WANC row with ConnType 4 (PPPoE_Bridged) and no IP/PPP fields filled. Which child row it
  owns is not verified: the factory hidden bridge sits on a WCPPP view.
- Factory default (in both the user and default DB): WCD1 holds a WANCIP row `WCIP1` with WANCEXT and seven
  WANCServList rows but **no WANC row**, and WCD2 holds the WANC/WANCPPP row `WCPPP1` with ConnType 4,
  HideListView 1 and IsSFUMode 1 (the hidden SFU pass-through). So a WANCIP/WANCPPP row can exist without a
  WANC row, and WANC rows with HideListView=1 are hidden from the stock list.
- `ServList` (bitmask INTERNET 1, TR069 2, VoIP 4, OTHER 8) and `StrServList` (text: `INTERNET`,
  `TR069,INTERNET`…) must be written together. The stock JS uses `SERVICELIST_PARA[ServList]`.
- The stock JS forces these values. IsNAT=0 for TR069/VoIP-only services and IPv6-only. dhcpEnable
  (= WANCEXT.DhcpEnable)=0 for TR069/VoIP. Priority=0 unless WBDMode=2. VLANID blank → 0. MCVlANID blank → -1.
  DSCP=-1 when disabled. Enable=1. IsADSL=0. ATMLinkType=EoA. TransType=PPPoE.
- Validation (`net_ethwan_conf_js.gch` pageCheckValue):
  - VLAN 1-4094 when tagged, otherwise 0-4094. DSCP 0-63. MCVLAN 0-4094.
  - Username 1-64 printable ASCII. Password 0-64. MaxUser 1..ProxyMaxUser. IdleTime 0-4294967295 (on demand).
  - MTU: PPPoE 128-1492, PPP + IPv6 1280-1492, static 128-1500, DHCP 576-1500, IP + IPv6 1280-1500.
  - Static IP, mask, gateway and DNS go through the usual IP checks.

### Recommended replacement-UI create sequence (the `wan-create` builtin)

This sequence is not verified on the device.

1. `sidbg 1 DB addr WANCD`, then set ViewName=IGD.WD1.WCD<n>, WANDViewName=IGD.WD1, LinkType=1, Enabled=1, IsDel=0.
2. `addr MultiWancd`, then set ViewName=…WCD<n>.MultiWancd, WCDViewName, Enable=1, VlanMode, WanVlan, WanPri.
3. `addr WANCPPP` or `WANCIP`, then set ViewName=…WCD<n>.WCPPP1|WCIP1 and the type fields.
4. `addr WANC`, then set the same ViewName plus WANCDViewName, Enable, ConnType, IPMode, ServList/StrServList,
   IsNAT, WBDMode, VLANID, Priority, WANCName.
5. `addr WANCEXT` (WANCViewName, DhcpEnable) and the WANCServList rows (dns 3, sntp 4, tr069 8…, copied from
   the factory pattern for the chosen ServList).
6. `save`, then reboot. A raw DB write skips cmapi's `CmHandleNodeNotifyMgr`, so the live stack is not told.
   The `apply` value is therefore set to `reboot`.

Open questions:
- Does `addr` fill ViewName itself?
- Do the max-WAN checks need anything else (`wanConnectExceedChk`, WANCD.WANCCapcity)?
- Where is port binding stored? The page parameter `bitBind` is a 0/1 string: LAN1..4, then SSID1..n. No DB
  table holds it, and PortBinding and L2BBridge are empty. The schema treats it as runtime.

### IPv6 WAN

The page parameters GUASrc, DNSv6Src, Gatewayv6Src, MTUv6Src, PrefixSrc, GUA1/2/3, Prefix1/Len,
Gatewayv6, DNS1-3v6, IPv6CPExt, GuaNum and PdNum exist in no dumped table. They probably live in
cspd's TR-181 `DEV.*` domain, which `sidbg 1 DB p` does not list. The schema exposes them only as
`runtime:wan_status` read-only fields. IPv6 WAN editing is unsupported until that storage is found.

### Actions

`dev_action` CmdId values: cmd_pppconnect, cmd_pppdisconnect, cmd_dhcpconnect (renew), cmd_dhcpdisconnect (release).

## Other WAN sub-pages

- **wan-user-pppoe** (ssmWANConnUser, user role only): edits WANCPPP.UserName/Password. ssmWANConnUserCom adds a ConnType select.
- **wan-client-limit** (pon_net_cltlmt): the stock page is read-only. Its OBJ_PON_USERLMT_ID fields do not match any DMs. CltLmt has
  9 rows, Type 0..8, with Enable/Max. Which Type code means which device class is not decoded.
- **dslite** (net_dslite_conf, net_dsliteeth_conf includes it): TUNNEL46CFG has 0 rows. The DMs are taken from the dslite_gch PARA
  (TUN46ViewName, TUN46WANCViewName, IsTUN46Enable, TUN46Localv4Addr, IsHMREMOTEAddrSrc, TUN46REMOTEIPAddr,
  Tunnel46name, Tunneltype=8) and are unverified. Marked `applicable: "unknown"`: the stack supports DS-Lite, but the ISP must provide it.
- **arp-detect**: ARPDETECTConfig (ArpEnable, Timeout 60-900, page param ArpAging → DM ArpAgeingtime 60-900).
- **dhcp-client** (dhcpcleanlink): page param bSendRelease → DHCPCComm.SendRelease. Inferred from the name.
- **mtu** (net_mtu_mtucg, user role): OBJ_MTU_CHANGE_ID MTUConfigSwitch (0 compat / 1 performance / 2 manual 1401-1491; 4/5
  lock the page). No table holds it, so the schema reads it from `runtime:mtu_change`.

## VLAN binding (`vlan-binding`)

OBJ_VLANBIND_ID has one instance per port (IGD.LD1.ETH1..4, IGD.LD1.WLAN1..n), with Mode (0 port, 1 VLAN) and
VLAN (`a/b` pairs, at most 4, each 1-4094, no duplicates). The VLANBIND table has 0 rows (view max 32), so
the row key DM is unknown. The list stays empty until the stock UI or the server creates rows.

## LAN and address management

- **lan**: the stock UI has no LAN page; the LAN IP sits in the DHCP server page (OBJ_BRGRP_ID → LAND row 0:
  IPAddr, NetMask (page param SubMask), AddressingType 1=static, IPv6Addr/IPv6PrefLen). On submit the stock
  page also writes DHCPSHostCfg.SubnetMask (= LAN mask) and DHCPSHostCfg.IPRouters (= LAN IP). The server should do
  the same and keep the pool inside the subnet.
- **dhcp-server**: DHCPSHostCfg row 0. The page params DNSServer1..3 map to the DB names **DNSServers1..3**.
  DnsServerSource: 1 = ISP DNS, 0 = manual. Lease options 60/3600/86400/604800 and -1 (infinite). Any other value
  is shown as custom. Leases are runtime (OBJ_DHCPHOSTINFO_ID).
- **dhcp-static**: DHCPSBind has 0 rows. The DMs (ViewName, HostCfgViewName, IPAddr, MACAddr) come from the page params and are unverified.
- **dhcp-device-pools**: DHCPSPool rows with PoolName hgw/stb/camera/phone/pc (VendorClassID `*`). The stock page edits only Min/MaxAddress.
- **dhcp-port**: the DHCPSPool per-port pools (PoolName eth1-4 / wlan0-15). ProcFlag=1 means DHCP is off on that port.
  The pppoeproxy1/2 pools are excluded.
- **ipv6-ra**: RaCfg uses renamed DMs: MinWaitTime→dwMinTime (3-1350), MaxWaitTime→dwMaxTime (4-1800),
  Mangment→bMangment, OtherCfg→bOtherCfg, ReachTime→dwReachTime, RetranTime→dwRetranTime. The page's
  `Enable` has no clear DM; bState is a bitmask (observed 243). Enable is left out until verified.
- **dhcpv6-server**: DHCP6SHostCfg plus LAND IPv6 (prefix length 48-64) plus DNSSettings (IPv6DNSConfigType, observed 2; the codes for the stock
  options WANConnection/Static/HGWProxy are unknown, so the field is plain int).
- **ipv6-lan-prefix**: OBJ_IPV6PREFIX_ID (Mode, Prefix, PrefixLen) has no table. LAND.IPv6GUAAddr/IPv6GUAPrefLen is a guess, so the page is `unknown`.
- **prefix** (smPrefixMgr): PrefixCfg has 0 rows. The DMs are the OBJ_PREFIX_ID params and are unverified.

## TR-069

- **tr069**: MgtServer row 0. Stock limits: URL 0-256, username 1-256 (required), passwords 0-256, inform interval 1-42949672.
  The stock page locks a field when its TR-069 attribute is 3, and hides the whole page unless ProInfoCfg.Tr069WebConfigEnable=1.
  Tr069Queue holds the DSCP/802.1p marking. `danger: confirm`.
- **tr069-cert**: CertID (inferred to be MgtServer.CertID) is chosen from a runtime list. Upload goes as multipart to `getpage.gch?pid=100`,
  field CertUpload, and needs a reboot.
- Menu3_NM_Loid (pon_net_loid_conf_t.gch, under smTR069) is a PON LOID page and was not mapped here.

## QoS

- **qos**: OBJ_QOSQB_ID covers two tables. QOSBasic holds Enable, QQRate, QQAlgorithmName SP/DWRR, QQBorrowEnable and DSCPRemarkEnable.
  QosCvpA holds VlanprioRemarkMode (0/1/2) and ModeName, the template string.
- The template page sends `Mode` as an ordered list such as `TR069,VOIP,IPTV,INTERNET` (or `OTHER`). Its DB home is taken to be
  QosCvpA.ModeName, because QOSBasic.Mode is an int; this mapping is inferred.
- **qos-queues**: QOSQueue has 8 upstream rows; DWQOSQueue has 4 downstream rows. Weight is 0-100 and applies only to DWRR/SP_DWRR. Statistics are runtime.
- **qos-rules**: QOSRule (Order, ClassQueue 1-8, VlanPrioMark 0-7, DscpMark 0-63, TCMark 0-255, PolicerQueue, ProtocolList).
  QOSType has 0 rows; the identity is probably IGD.QOS.QRn.QTm, and the DM linking a type to its rule is unknown.
- **qos-policers**: QOSPolicer has 0 rows (view max 10); the DMs are unverified.
- **qos-app**: OBJ_QOSQA_ID (AppName, ClassQueue) has no backing table, so it is runtime/unknown.
- **qos-basic-yn / qos-stats-yn**: province (YN) variants, marked `applicable: false`.

## SNTP, routing, ADSL

- **sntp**: SNTP row 0. Page params ZoneIndex/PosixTimeZoneName map to iZoneIndex/sPosixTimeZoneName.
  NTPServerType: 0 INTERNET, 1 VoIP, 2 TR069, 3 OTHER, 4 Auto. Poll interval is 0 or 3600-604800. Dscp is 0-63, with -1 meaning off.
  The time zone list is `timeZoneArray` in net_sntp_conf_js.gch; LocalTimeZone, LocalTimeZoneName and iZoneIndex must stay consistent with it.
- **rip**: RIPConf plus RIPIf (IfId = IGD.LD1, ETHn, WLANn). The enum codes need on-device confirmation (see above).
- **static-routes**: L3ForwardingRT (view RT under L3F) has 0 rows. The DMs are the OBJ_ROUTESTATIC_ID params
  (Enable, Interface, DestIP, DestIPMask, GWIP, …) and are unverified; TR-098 names such as DestIPAddress are possible.
  Validation: a /32 mask requires a host address, and the gateway must not be 0.0.0.0.
- **route-table**: runtime (OBJ_ROUTETABLE_ID).
- **adsl**: `applicable: false`. The device is GPON and there is no leaf page.

## Apply and danger

- `apply: reboot` is a best guess for DB-backed pages. `sidbg DB set` and `save` change the stored config, but cmapi's node
  notification (`CmHandleNodeNotifyMgr`) never runs, so running services are not reconfigured.
- `danger: commit-confirm` on these pages: wan, wan-user-pppoe, dslite, vlan-binding, lan, dhcp-server and rip/static-routes.
  `danger: confirm` on tr069 and tr069-cert.
