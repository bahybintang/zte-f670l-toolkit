# Application and Administration pages: mapping notes

Covers `pages/application.json` (32 pages) and `pages/admin.json` (13 pages).
Sources: stock UI `debug/clone-fw/httpd/` (dmenu.conf, `*_t.gch`, handler `*.gch`, `*_js.gch`,
langen.conf), DB table/DM names from `debug/decoded/db_user_cfg.plaintext.xml`, the clone's
`backup/bin/httpd` and `backup/bin/cspd` (strings only), and the reference firmware
`debug/ref-fw-v9/extracted` (genuine ZTE, used only for corroboration).
`pages/*.json` was generated by a script so the JSON stays valid. Every DB section's table is in
`tables.txt`, and every DM exists in the user DB, except the two tables that have 0 rows (see U1).

## Builtin actions and how stock does them

`dev_action(CmdId=…)` in a gch sends a command to cspd. Our server cannot call that directly.

| Action id | Stock mechanism | Replacement |
|---|---|---|
| `reboot` | `manager_dev_conf_t.gch` POST `IF_ACTION=devrestart` → `equip_gch.gch` `dev_action(cmd_devrestart)`; also `ajaxComLogic.gch?pid=1 IF_ACTION=devRestart` (the VoIP switch uses it) | `sidbg 1 DB save`, then `reboot` (already in `actions.rs`) |
| `factory-reset` | `IF_ACTION=devrestoreR` → `cmd_factoryreset`; cspd logs "RESTORE default" and loads `/userconfig/cfg/db_default_cfg.xml` at the next boot. `devrestore` → `cmd_devrestore` exists but no page uses it | **Unproven.** Option A: POST the stock webd endpoint with a stock session. Option B: remove `db_user_cfg.xml` and `db_backup_cfg.xml` from `/userconfig/cfg`, then reboot. fw_flashing does this unlink on a protocol change, after which cspd falls back to the default config. Take a full-flash backup before testing B |
| `backup-download` | No web backup page on this build; only USB backup | Stream `/userconfig/cfg/db_user_cfg.xml` (ecb-zero container; `zte670 unpack-db` decodes it). Already implemented as `/api/backup/download`. The file contains every secret |
| `backup-restore` | USB restore at boot (below). httpd also accepts `ConfigUpload` / `DefCfgUpload` through `getpage.gch`, but no menu page uses them | Check the upload decodes as a DB container, write it to `db_user_cfg.xml` **and** `db_backup_cfg.xml`, then reboot without running `sidbg DB save` (which would overwrite the file). This is the README procedure, already proven by hand |
| `firmware-upgrade` | see below | Hand the image to the stock path; do not write mtd yourself |
| `usb-backup` | set_inst `OBJ_USBBAKRST_ID {SelectPath, StartBackup=1}` + undoDBSave. cspd writes `<usb>/<BakDir>/<BakFileName>` (default dir `e8_Config_Backup`, ctce8 cfg format, as handled by `zte670 pack/unpack`) | needs the cspd message; no shell equivalent known |
| USB restore | `UsbBakRst.RstEnable=1`; at boot cspd `dbFileUSBRestore` opens `/mnt/<usb>/<BakDir>/<BakFileName>`, then checks the version and sign headers, decrypts, decompresses, compares and replaces the config | an ordinary DB write (page admin-usb-restore) |
| `log-clear` | `IF_ACTION=clearlog` → `cmd_clearlog` | needs cspd, or truncate the log files |
| `log-download` | POST `getpage.gch?pid=101&<token>`, field `downloadlog`. httpd calls `pm_log_get_log_file` and serves the result as `log_file.log` (strings mention `/var/userlog.txt`) | read the log file directly |
| `maintenance-over` | `IF_ACTION=testover` → `cmd_testover` | needs cspd; operator-only |
| `voip-register` / `voip-unregister` / `voip-reset` | set_inst `OBJ_PON_VOIPLOGOUT_ID {LineNumber (index, or 255 = whole device), LogState (0 = register, 1 = unregister, 2 = power reset)}` + undoDBSave | needs cspd |
| `ftp-download-start` / `-cancel` | set_inst `OBJ_FTPCLIENT_ID` with `DownloadCtl` 0 = start, 1 = cancel, 2 = overwrite | needs cspd, or use busybox ftpget directly |

### Firmware upgrade, step by step

1. `manager_dev_version_t.gch` takes a CSRF token from `get_csrf_session_token()`, checks it
   through `checkSessionToken.gch`, then sends a multipart POST to
   `getpage.gch?pid=100&<token>&nextpage=…` with the file field `VersionUpload`.
2. `getpage.gch` is not a template file; httpd handles it internally. It refuses the upload when
   Content-Length is larger than free memory, writes the image to `/var/tmp/fw.bin`, and calls
   `CmUpgradeStart` (`pm_upgrade_start`), which pushes the job to cspd `upgrade_mgr`.
3. cspd `upgrade_mgr.c` runs `UpgradeCheckUpgradeFile` / `UpgradeCheckFirmware` /
   `verifyCspFwMagic`. These read the "zxic_Header" firmware header (`dwWhichDefault` selects
   whether the default config is reset) and run `UpgradeCheckUpgradeKey`. It then kills processes
   (`upgradeKillProcBeforeFlash`) and spawns
   `fw_flashing -d %d -r %d -p %ld -t %d -f /var/tmp/fw.bin`, or `boot_flashing …` for a
   bootloader image.
4. `fw_flashing`: the reference build checks the magic, `/proc/csp/boardtype` and the software
   version (`check software version error`, `allow_back_up`). It writes the **inactive** image
   bank (dual image, `Image0Status`/`Image1Status`, `/dev/mtd7`/`mtd8` on the reference board),
   records `/userconfig/upgrade_record`, and reboots. If the media protocol changes, it also runs
   `echo 1 > /userconfig/cfg/protocol_flag.file` and unlinks the user DB files.
5. Progress comes from `manager_version_query_t.gch`, which polls `OBJ_UPGRADE_ID`
   `UpgardeStatus` (`SUCC` / `UPLOAD_FINISH` / `REBOOTING`; the misspelling is the firmware's own)
   and `Percent` (508 maps to message `upg_508`; any other failure maps to `upg_401`).

Steps 1–3 come from the clone's httpd/cspd strings. The fw_flashing details in step 4 come from
the reference rootfs, because the clone's `fw_flashing` binary is not in the repo. Pull
`/bin/fw_flashing` from the device before relying on step 4.

## Top uncertainties

- **U1 Empty tables.** `FWPM` (port forwarding) and `DNSHostsList` (hosts) have 0 rows, so the
  DM names come from the handler PARA lists. `DNSHostsList` as the table behind
  `OBJ_DNSHOST_ID` is a guess by name. Check both with `sidbg 1 DB pti <Tbl>` and do one add.
- **U2 OBJ→DB renames found by name matching:** IGMP/MLD snooping (`Enable`/`MtoU` →
  `LAND.IGMPSNPEnable`/`IfMtoU`); hook-flash (`FlashLowMin`/`HookLow` → `*Time`); RTP QoS
  (`RTPDSCPMark` → `VoIPRTPCfg.DSCPMark`); loop detection (`DMac`/`Sendinterval`/`VidStr` →
  `DMACAddr`/`SendInterval`/`VlanTag`; the units of `SendInterval` look like ms); IGMP/MLD proxy
  WAN (`IGMPProxy.WanCID` or an `IGMPWan` row?); monitor (`MonitorCollectorCfg` or
  `MONITORCONFIG`).
- **U3 Unit conversions the schema cannot express.** The fields are stored raw. Stock shows
  InviteExpires in minutes (stored in s), the call timers in s (stored in 10 ms), the voice gains
  as `dB = v/10 − 14`, EtherType in hex, and the DMS content list encoded as
  `/mnt<path>|…`. Units and help text describe each conversion. A `scale`/`offset` field
  attribute would let the UI show the stock units.
- **U4 Apply semantics.** Stock writes go through cspd `set_inst`, which notifies the module.
  `sidbg 1 DB set` probably does not, so DB pages are marked `apply: reboot` until tested.
  admin-users is `save`, because the web login reads the DB.
- **U5 Linked writes.** Stock sets `IfMtoU` equal to the IGMP enable box, sets `MaxIntPort`
  equal to `MinIntPort`, copies the WAN option text into `WANCName` (DMZ), and sets
  `WanType=2` (IGMP proxy). The server must reproduce these, or the user sets them by hand
  (they are `advanced`).
- **U6 WAN pickers.** `Interface`, `WANCViewName` and `WanCID` take a WAN ViewName. The schema
  has no dynamic options, so a `runtime:wan_connections` option source would help.
- **U7 Applicability.** H.248 pages are `false` while `ProtocolSet=4`. IPTV is `unknown`
  (dmenu upMode=2 and Ethernet-WAN objects). The maintenance report, service account numbers
  and monitor pages are `unknown` (operator features). VoIPPortCfg reports `FxsNum=1`, so the
  VoIP pages apply. Note that the README describes the board as an EPON F628S, while the task
  brief says GPON; nothing in these pages depends on which.
- **U8 DevAuthInfo rows 2–5** (AppID 2/4/5) are not identified; only the web rows 0/1 are exposed.

## Security findings (outside the schema, worth knowing)

- `telnet.gch` turns on LAN telnet (`TelnetCfg.TS_Enable`) for any request whose query string
  carries a hard-coded user/password pair. It is an unauthenticated backdoor. Do not proxy or
  re-expose it.
- The clone's httpd contains `cp -rf /mnt/usb1_1/H2128S-2WLED-F670L-SDK/yyk_run.sh /tmp/yyk_run.sh`,
  `chmod 777` and `/tmp/yyk_run.sh &`. These lines suggest httpd runs a script from a USB stick
  with a specific folder name. The trigger was not traced.
- The DDNS password is only base64-encoded on read (`strencode`). The admin password is a plain
  `DevAuthInfo.Pass`.
